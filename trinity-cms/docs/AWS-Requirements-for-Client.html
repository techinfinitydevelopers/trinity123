Moving the Trinity website to AWS

What we need from you, in simple words

1. What is happening?

The Trinity website is working today on another hosting service. You asked for it to run on AWS (Amazon Web Services) instead. Think of AWS as a big, reliable building where the website, its database and its photos are kept. Nothing changes for your visitors. The website looks and works the same. Only the "building" it lives in changes.

3. What will be set up on AWS (and why)

AWS servicePlain meaning
App RunnerRuns the website. It restarts itself if something fails and gives a secure (https) address.
RDS (database)Keeps all the content: pages, blog posts, leads, country details. It is backed up automatically every day.
S3 (file storage)Keeps all uploaded photos, such as university images.
Route 53 / DNSPoints your domain name to the new website.

5. How the move works

  1. Preparation (our side): we prepare the website so it runs on AWS. Nothing changes on the live site.
  2. Setup: with your AWS login, we create the services above.
  3. Copy: we copy the content and photos to AWS. The old site keeps running meanwhile.
  4. Testing: we test every page, the admin panel, the forms, uploads and the chatbot on a temporary AWS address.
  5. Go-live: in the agreed time slot, the domain is pointed to AWS.
  6. Safety period: the old hosting stays on for a few days as a backup, then it is switched off.

Expected time: about 3 to 5 working days after we receive the AWS access.

Safety rules. Never send passwords or secret keys over WhatsApp or email. Use the IAM user above, and share any key through a password manager or a private call. After the work, the access can be removed.
